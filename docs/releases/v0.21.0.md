# v0.21.0 Release Notes

**Release Date:** August 22, 2026

## Highlights

This release introduces the **residual risk model** — vulnerability severity and risk before and after compensating controls, with exception-driven SLA switching — and **titled vulnerability reports** in Markdown, HTML, and PDF via the new `reports/vulnreport` package and `govex report` subcommand.

## New Features

### Residual Risk Model

Vulnerabilities now carry their assessment before and after compensating controls, without relabeling the inherent severity:

- **`CompensatingControl`** - Controls with function (preventive/detective/corrective), reduced risk dimensions, the CVSS environmental metrics they justify (`ModifiedMetrics`), effectiveness, and verification state
- **`ExceptionStatus`** - Risk exception approval state with expiry
- **Residual fields** - `SeverityResidual`, `SeverityResidualVector`, `RiskInherent`, `RiskResidual`, `Controls`, `Exception`
- **Effective severity** - The SLA clock runs on inherent severity until an exception is approved, then on residual severity while the approval is in effect
- **Validation** - Residual severity is restricted to Critical-Low and can never exceed the inherent severity

```go
vn := govex.Vulnerability{
    Severity:         "High", // inherent: 30-day SLA
    SeverityResidual: "Low",  // residual: 180-day SLA
    Controls: []govex.CompensatingControl{{
        ID:              "CTRL-NET-001",
        Name:            "Network segmentation",
        Function:        govex.ControlFunctionPreventive,
        Reduces:         []string{govex.ReducesLikelihood},
        ModifiedMetrics: []string{"MAV:A"},
        Verified:        true,
    }},
    Exception: &govex.ExceptionStatus{
        Status:     govex.ExceptionStatusApproved,
        ApprovedAt: &approvedTime,
        ExpiresAt:  &expiryTime,
    },
}
sev := vn.EffectiveSeverity(time.Now()) // "Low" while approval is in effect
```

See [Compensating Controls & Residual Risk](../reference/residual-risk.md).

### Risk Package

The new `risk` package models organization-level risk, distinct from CVSS-derived severity:

- **`Rating`** - Likelihood × impact assessments with matrix reference, rationale, confidence, and assessor attribution
- **`Matrix`** - Explicit likelihood × impact policy objects referenced by ID
- **NIST SP 800-30** - Level constants mapping 1:1 to the canonical scale (Very High↔Critical … Very Low↔Negligible), the standard's semi-quantitative 0-100 values, and translators for FedRAMP-style rendering

### Version-Specific CVSS Rating Scales

The `cvss` package aligns severity bands with the [NVD qualitative ratings](https://nvd.nist.gov/vuln-metrics/cvss), per CVSS version:

- CVSS v3.x and v4.0: None 0.0, Low 0.1-3.9, Medium 4.0-6.9, High 7.0-8.9, Critical 9.0-10.0
- CVSS v2.0: no None or Critical; Low 0.0-3.9, High 7.0-10.0 — legacy v2 scores are never relabeled with v3/v4 bands

### Vulnerability Reports (vulnreport)

The new `reports/vulnreport` package renders a `VulnerabilitiesSet` as a titled report:

- **Metadata** - Title, subtitle, organization, author, classification banner, period, executive summary
- **Sections** - Severity summary table, findings table, and per-finding detail blocks with residual severity/risk and compensating controls
- **Formats** - Markdown (GFM), standalone HTML (escaped, styled), PDF (maroto), and JSON round-trip
- **Columns** - Default and residual-aware findings column sets, or custom column definitions

### govex report Subcommand

```bash
# HTML report from a vulnerabilities set JSON
govex report -i vulns.json -o report.html

# PDF with metadata and residual columns
govex report -i vulns.json -o report.pdf \
  --title "Q3 Vulnerability Report" \
  --classification "Confidential" \
  --columns residual
```

The input may be a `VulnerabilitiesSet` JSON (e.g. from `govex merge`) or a saved `Report` JSON; the output format is inferred from the file extension (`.md`, `.html`, `.pdf`, `.json`).

## Fixes

- **SLA status inversion** - `severity.SLAStatusTimesString` returned "Within SLA" for overdue items and "Out of SLA" for compliant ones, inverting the SLA status column in generated reports
- **Severity score table** - The severity-to-score markdown table showed Low as 1.0-3.9 instead of 0.1-3.9
