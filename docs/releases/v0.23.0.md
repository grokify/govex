# v0.23.0 Release Notes

**Release Date:** October 5, 2026

## Highlights

POA&M generation is now **scanner-agnostic**. The new
`reports/poam.FromFindings` renders a POA&M table from a slice of
[findingspec](https://github.com/plexusone/findingspec) findings, so any adapter
that emits the shared findingspec IR — AWS Inspector, Grype, Trivy, and others —
can produce a Plan of Action & Milestones through a single entry point.

## Added

### POA&M from findingspec

```go
import (
    "github.com/grokify/govex"
    "github.com/grokify/govex/reports/poam"
    "github.com/plexusone/findingspec"
)

// findings is []findingspec.Finding produced by any adapter.
tbl, err := poam.FromFindings(findings, &govex.ValueOptions{}, nil)
```

- `reports/poam.FromFindings([]findingspec.Finding, *govex.ValueOptions, overrides) (*table.Table, error)`
  renders a POA&M `*table.Table` from findingspec findings.
- `reports/poam.Finding` wraps a `findingspec.Finding` as a `POAMItem`,
  resolving open/closed status, per-field values, CVE identifiers, and
  remediation-plan text from the finding's security detail. Non-security
  findings degrade gracefully (dependent fields fall back to empty).

This complements the existing POA&M item interface: callers that already have
findingspec findings no longer need a scanner-specific adapter to generate
POA&M output.

## Dependencies

- Added `github.com/plexusone/findingspec` v0.1.0.
- Updated `github.com/grokify/mogo` to v0.75.0, `github.com/relvacode/iso8601`
  to v1.8.1, and `github.com/johnfercher/maroto/v2` to v2.4.3.
- Pinned `github.com/pdfcpu/pdfcpu` to v0.15.0 and excluded v0.16.0 / v0.16.1:
  those versions changed the `api.LoadConfiguration` / `api.MergeRaw`
  signatures and break maroto's PDF merge package used by the vulnerability and
  pentest reports. The `exclude` directive in `go.mod` documents this and
  prevents reselection.
